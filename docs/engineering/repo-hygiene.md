# Repository Hygiene

This document defines the repository-wide hygiene rules for local development, CI, and generated artifacts.

## Canonical Python Resolution

Use the repository `.venv` as the canonical Python environment after editable installation is complete.

Resolve the interpreter with:

```bash
python qa/scripts/resolve_python.py .
```

Resolution order is fixed:

1. `<repo>/.venv/Scripts/python.exe`
2. `<repo>/.venv/bin/python`
3. System `python`

Use the resolved interpreter for:

- `pytest`
- integration gates
- local verification scripts
- Python-based QA tools

## Generated Files

Approved checked-in generated files must remain deterministic.

- `desktop/src/routeTree.gen.ts` is generated by the TanStack Router build path.
- Do not edit generated files manually.
- Verify the desktop generated route tree with:

```bash
cd desktop
npm run build:verify-generated
```

CI also enforces:

```bash
git diff --exit-code -- desktop/src/routeTree.gen.ts
```

## Clean-Tree Validation

Run these commands before opening a PR:

```bash
python openbb_platform/dev_install.py -e
python openbb_platform/dev_install.py -e --cli
python -m pytest openbb_platform/tests/test_dev_install.py -q
python -m pytest openbb_platform/tests/test_pyproject_toml.py -q
pwsh ./qa/scripts/run_integration_gate.ps1 -DryRun
pwsh ./qa/scripts/run_full_verification.ps1 -DryRun
cd desktop && npm ci && npm run build:verify-generated
git status --porcelain
```

The repository should be clean after verification.

## Local Scratch Files

Use dedicated directories for local-only scratch artifacts:

- `.tmp/local/`
- `.logs/local/`

Do not add new root-level scratch filenames. Existing explicit root ignore entries are legacy compatibility only.

## CI Rules

- Do not use bare `pytest` in CI after editable install. Use the interpreter resolved by `qa/scripts/resolve_python.py`.
- `dev_install.py` is fail-fast and restores temporary file changes if installation fails.
- Pre-commit and CI both enforce line-ending and scratch-file guardrails.
